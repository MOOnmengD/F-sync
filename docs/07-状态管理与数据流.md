### `chat.ts` — 聊天消息

**文件**：`src/store/chat.ts`

**持久化**：✅ `localStorage`（key: `f-sync-chat-v2`），Zustand persist middleware

**接口**：
```typescript
interface ChatMessage {
  id: string          // 客户端生成：{timestamp}-{random}
  role: 'user' | 'assistant' | 'system'
  content: string
  createdAt: number   // 毫秒时间戳
  isSynced?: boolean  // 是否已同步到 Supabase
  images?: string[]   // base64 图片（仅 user 消息，不同步云端）
  imageSummary?: string // 聊天识图摘要（仅本地缓存，不同步云端）
  imageSummaryModel?: string // 生成摘要的视觉模型名
  webSearchContext?: WebSearchContext[] // 网页检索 AI 的结论与来源，本地 + 云端同步
}
```

**操作**：

| Action | 说明 |
|--------|------|
| `addMessage(msg)` | 添加消息，生成客户端 ID，标记 `isSynced: false` |
| `upsertMessage(msg)` | 按 ID 防重插入/更新（用于 Realtime 同步） |
| `updateMessage(id, updates)` | 更新消息字段 |
| `deleteMessage(id)` | 删除（本地 + Supabase 级联，按 client_id 和 UUID 双重删除） |
| `syncMessages()` | 批量同步未同步消息到 Supabase `chat_messages` |
| `clearMessages()` | 清空本地消息 |
| `setLoading(v)` | 设置加载状态 |
| `setHasMore(v)` | 设置是否还有更多历史消息 |

**同步机制**：
- 页面卸载/隐藏时自动触发 `syncMessages()`（`beforeunload` + `visibilitychange` 事件）
- 同步时跳过 `role === 'system'` 的消息
- `client_id` 字段用于幂等防重
- assistant 消息的 `webSearchContext` 同步到 `chat_messages.web_search_context`；不保存网页搜索片段
- 组装最近 30 条消息时，将仍在窗口内的检索结论作为隐藏上下文附加到对应 assistant 消息；消息退出窗口后自然移除

**Realtime 集成**：
- 应用级监听 `chat_messages` 的 INSERT（`App.tsx` 中）
- 检测 `proactive-` 前缀 → 触发原生通知
- Chat 页组件级监听新消息 → `upsertMessage` 更新本地列表

### `settings.ts` — 应用设置

**文件**：`src/store/settings.ts`

**持久化**：✅ `localStorage`（key: `f-sync-settings`）+ 云端 Supabase `user_settings` 表

**接口**：
```typescript
interface AISettings {
  systemPrompt: string
  userPrompt: string
  postHistoryPrompt: string
  proactivePrompt: string
  homeModePreferences: HomeModePreferences
  apiConfigs: ApiConfig[]
  parseTransactionConfig: ParseServiceConfig
  parseMediaConfig: ParseServiceConfig
  ttsConfig: TtsServiceConfig
  investmentOcrConfig: InvestmentOcrConfig
  chatVisionConfig: ChatVisionConfig
}

interface HomeModePreferences {
  pinnedModes: QuickMode[] // 默认 finance/invest/media，最多 3 个
  modeOrder: QuickMode[]   // 8 个主页模式的展示顺序
}

interface ApiConfig {
  name: string
  url: string
  key: string
  model: string
  enabled: boolean
}
```

**操作**：

| Action | 说明 |
|--------|------|
| `updateSettings(updates)` | 部分更新设置 |
| `loadFromCloud()` | 从 Supabase `user_settings` 拉取，云端优先合并；无记录、未登录或查询失败时也会结束加载态 |
| `saveToCloud()` | 推送本地设置到 Supabase（先备份当前云端版本到 `previous_settings`） |

**合并策略**：
- 使用 `??` 运算符（允许远程清空字段）
- `apiConfigs`：云端有则用云端（自动迁移旧格式），否则保留本地
- `homeModePreferences`：使用 `normalizeHomeModePreferences()` 过滤非法 mode、去重、补齐缺失 mode，并限制置顶最多 3 个
- 加载时自动迁移无 `name`/`enabled` 字段的旧 apiConfigs

**默认值**：
- `systemPrompt`：Florian 角色设定（硬编码默认值）
- `proactivePrompt`：主动消息指令（硬编码默认值）
- `homeModePreferences`：默认置顶 `finance/invest/media`，默认顺序 `finance/invest/media/review/note/work/save/timeline`
- `apiConfigs`：2 个空配置槽（`enabled: true`）
- `investmentOcrConfig`：空配置，理财截图 OCR 默认走 `OCR_AI_*` / `CHAT_AI_*` / `AI_*` 环境变量和默认 prompt
- `chatVisionConfig`：默认 `mode='direct'`，即图片直传主聊天模型；切换为 `vision_summary` 后使用独立视觉模型生成图片摘要

## Hooks

### `useTimeline`

**文件**：`src/hooks/useTimeline.ts`

计时器逻辑 hook，支持跨页面刷新持久化。

**状态**：
- `kind`：计时类型（睡眠/生活/工作/娱乐）
- `running`：是否正在计时
- `durationLabel`：格式化时长（HH:MM:SS）
- `tick`：每秒递增的计数器（驱动 UI 刷新）

**持久化**：`localStorage`（key: `fsync.timeline.active.v1`），存储 `{timing_type, start_time}`

**操作**：
| 操作 | 说明 |
|------|------|
| `handleStart()` | 开始计时（写入 localStorage） |
| `handleStop()` | 停止计时 → 写入 transactions 表 → 清除 localStorage |
| `handleCancel()` | 取消计时（不保存） → 清除 localStorage |
| `handleKindChange(k)` | 切换类型（自动结算上一段） |

**切换类型逻辑**：
- 未开始 → 仅切换类型
- 已开始且同类型 → 无操作
- 已开始且不同类型 → 自动结算上一段（写入 DB）→ 开始新计时

### `useFinanceDashboard`

**文件**：`src/hooks/useFinanceDashboard.ts`

主页记账模式的消费面板数据 Hook，不新增 Zustand 状态。

**职责**：

- 查询当前月记账，派生必需/总支出/非必需汇总、每日消费和选中日期记录；
- 分页查询全部历史记账，计算最多三个快捷记录组合；
- 监听 `transactions` INSERT / UPDATE / DELETE，并在窗口重新获得焦点时刷新；
- 快捷记录直接复制最近模板写入 `transactions`，跳过 AI 解析但仍触发向量化；
- 普通记账成功后由 `Home.tsx` 调用 `refresh()` 主动更新。

主页局部状态 `selectedFinanceDate` 默认是今天，不进入 Zustand 或 localStorage。

## 离线草稿箱

**文件**：`src/pages/Home.tsx`（内嵌逻辑）

**机制**：
- 发送前将消息存入 `localStorage`（key: `fsync_outbox`）
- 发送成功 → 移除草稿
- 发送失败 → 保留草稿，Toast 提示「已保存在本地草稿」
- 恢复草稿时重新填入输入框

**数据结构**：
```typescript
type OutboxEntry = {
  id: string        // 客户端 UUID
  mode: QuickMode   // 记录模式
  raw: string       // 原始输入文本
  ts: number        // 时间戳
}
```

## 理财本地草稿

**文件**：`src/components/InvestmentPanel.tsx`

理财页的持仓快照和策略参数编辑采用组件内本地草稿，不进入 Zustand：

| 状态 | 说明 |
|------|------|
| `funds` | 当前页面显示的数据，会被行内编辑和 OCR 套入立即更新 |
| `savedFundsRef` | 最近一次从 Supabase 读取或成功保存后的远端快照，用于计算差异 |
| `pendingUpdates` | 待同步修改，按 `investmentId` 记录持仓、收益率、建议持仓、止盈线的差异 |
| `pendingCreates` | OCR 产生的待新增基金，使用 `ocr:` 临时 ID；保存前显示在持仓表，但不写入 Supabase、不参与调仓建议计算 |
| `formulaConfig` | 当前调仓公式配置，从 `localStorage` 读取 |

**交互流程**：

```
点击表格数字 → 输入新值
  → 点击「确定」：更新 funds + pendingUpdates，清除该基金旧建议
  → 点击数字区域外：取消本次输入，不改 funds

点击买入/卖出建议金额 → 输入实际调仓金额（默认带入建议值）
  → 点击「确定」：POST /api/investment type=action，更新当前持仓并清除该基金建议
  → 金额等于建议值时记录为 confirm_suggestion，否则记录为 override_suggestion
  → 点击建议编辑区域外：取消本次输入，不执行调仓

点击「计算建议」
  → 使用当前 funds + formulaConfig 在前端纯函数计算
  → 不依赖 pendingUpdates 是否已同步到 Supabase

点击「保存 N」
  → 将 pendingUpdates + pendingCreates 一并 POST /api/investment type=batch_update
  → 成功后重新读取 Supabase 持仓，以正式 UUID 替换临时 ID
  → 清空 pendingUpdates + pendingCreates

点击「上传截图」
  → 选择一张或多张图片
  → 逐张 compressImage() 压缩为 WebP data URL
  → 读取 settings.investmentOcrConfig
  → 逐张 POST /api/investment type=ocr
  → 先按标准化完整名称去重，重叠截图只覆盖非空值
  → 名称主体相同且末尾为不同 A/C/E 类时合并金额，并按成本合并收益率
  → 已匹配项套入 funds + pendingUpdates
  → 未匹配项可编辑名称/金额/收益率，确认后进入 funds + pendingCreates
  → 多个数据库目标冲突时由用户选择；未选择则忽略
```

**公式配置**：

- 存储位置：`localStorage`
- key：`fsync.investment.formula.v1`
- 内容：补仓阈值与金额上限、止盈比例、强止盈参数等 `InvestmentFormulaConfig`；历史版本保存的再平衡字段会被忽略

## 核心数据流

### 记账/记录流程

```
用户输入 (Home.tsx)
  → 前端预处理
    ├── extractDate() → 提取日期
    └── extractAmount() → 提取金额
  → 决定最终日期
    ├── 正文有日期 → 正文日期优先
    ├── 正文无日期 + 日历选中历史日期 → 日历日期
    └── 正文无日期 + 日历选中今天 → 数据库当前时间
  → 离线草稿箱（预存）
  → POST /api/parse-transaction（AI 解析）
  → items 表查询/创建（按 item_name 去重）
  → transactions 表写入
  → 异步 POST /api/vectorize（生成 embedding）
  → 移除草稿
  → 主动刷新主页消费面板
  → Supabase Realtime → Home/Finance/Whisper 实时更新
```

### 主页消费面板与快捷记录

```text
进入主页记账模式
  ├── 查询当前月记账
  │   ├── necessity=true → 必需支出
  │   ├── necessity=false/null → 非必需支出
  │   ├── 按本地日期聚合每日金额 → 四档日历颜色
  │   └── 按 selectedFinanceDate 筛选当天记录
  └── 分页查询全部历史记账（1000 条/页）
      → 按 item_name_snapshot + amount + review 分组
      → 总次数 >= 3
      → 总次数 / 首次出现月至当前月自然月数 >= 1
      → 次数降序、最近出现时间降序
      → 同显示名称+金额去重
      → 取前三个快捷按钮

点击快捷按钮
  → 复制该组合最近一条记录的业务字段
  → 日期使用当前日历选中日期
  → 直接写入 transactions（不调用 AI）
  → 异步调用 /api/vectorize
  → 刷新汇总、日历、当天记录和快捷统计
```

### 书影连续点评流程

```text
进入主页「书影」模式
  → 查询 media_items(status='consuming')
  → 以标题胶囊展示，按 updated_at 倒序

新增条目
  → /api/parse-media 解析标题/点评
  → Supabase RPC save_media_record
    ├── 创建 media_items 当前快照
    └── 创建 media_item_events 初始事件

点击“正在看”标题 → 输入新点评
  → 不调用 AI 解析
  → Supabase RPC save_media_record
    ├── 更新 media_items.review / status
    └── 创建 media_item_events 点评/状态事件
  → 发送成功后取消标题选择
  → 仍为 consuming：保留胶囊
  → 改为其他状态：移除胶囊
```

主页局部状态 `activeMediaItems`、`activeMediaLoading`、`selectedMediaItemId` 不进入 Zustand；`media_items` Realtime 和窗口 focus 会触发重新查询。

### AI 对话流程

```
用户发消息 (Chat.tsx)
  → 本地状态（addMessage → Zustand persist → localStorage）
  → POST /api/chat-completion
    ├── 聊天图片理解
    │   ├── direct：图片进入 image_url parts
    │   └── vision_summary：未缓存图片 → 视觉模型生成摘要；已有 imageSummary → 直接复用
    ├── 基础上下文构建（enrichMessages）
    │   ├── RAG 三策略检索
    │   ├── 记忆检索（判断 + 事件匹配 + 对话回捞）
    │   └── 真实世界信息注入
    ├── 多模态转换（图片 → image_url parts）
    ├── 只读 Agent 工具循环（最多 2 轮，按实际配置暴露工具）
    │   ├── list_fsync_domains / describe_fsync_domain
    │   ├── query_fsync_records
    │   ├── search_memories / search_life_logs
    │   ├── search_web（智谱结构化搜索，每个请求最多 2 次）
    │   └── 生成 AgentContextItem + 简要 agentTrace
    ├── 若执行网页搜索：当前对话模型作为检索 AI
    │   ├── 临时读取最多 5 条网页标题/摘要/来源
    │   ├── 生成简短检索结论
    │   └── 原始网页片段丢弃，仅保留结论与来源
    ├── 最终上下文重排（工具结果进入时间线或本轮工具查询摘要）
    └── 多组 API 轮询
  → AI 响应 → addMessage('assistant')
  → 若返回 imageUnderstanding → 写回对应 user 消息的 imageSummary / imageSummaryModel
  → 若返回 webSearchContext → 写回对应 assistant 消息并参与后续最近 30 条上下文
  → syncMessages() → Supabase（按 client_id 防重，含 web_search_context）
  → 页面卸载/隐藏时自动同步未发送消息
```

> 用户画像和社交关系不再每轮固定注入 Chat 上下文；Florian 需要时通过只读 Agent 工具查询 `user_profile_facts` / `social_relationships`。

### 设置同步流程

```
Home / Chat / Settings 页挂载 → loadFromCloud()
  → Supabase user_settings 表拉取
  → 有云端设置：云端优先合并到本地 Zustand
  → homeModePreferences 归一化后用于主页模式栏置顶与排序
  → 无云端记录或查询失败：保留本地设置，并结束加载态

保存设置 → saveToCloud()
  → 读取当前云端版本 → 备份到 previous_settings
  → upsert 到 user_settings
```

### 文本解析配置使用

```
记账/点评 → parseTransactionConfig → /api/parse-transaction

书影新增 → parseMediaConfig → /api/parse-media
  → 若 parseMediaConfig.url/key/model 为空，复用 parseTransactionConfig.url/key/model
  → systemPrompt/userPrompt 不复用记账解析，空值继续使用书影默认 Prompt
```

### 主动消息流程

```
GitHub Actions (每15min)
  → curl POST /api/proactive-ai
  → 鉴权 (CRON_SECRET)
  → 静默检查（1h内有对话？）
  → 上下文构建（与 chat-completion 共享管线）
  → AI 决策（发送/跳过）
  → 发送：
    ├── chat_messages 写入（client_id=proactive-{ts}）
    ├── Supabase Realtime → 前端通知
    └── 华为 Push Kit v3 → 设备推送
  → 画像异步更新
```

### 每日摘要流程

```
GitHub Actions (每天 UTC 17:00)
  → curl POST /api/daily-summary
  → 鉴权 (CRON_SECRET)
  → 收集过去 24h 数据
  → 四步流水线：
    1. AI 日记生成 → daily_logs
    2. 社交关系更新 → social_relationships
    3. 每日事件提取 → daily_event_items + embedding
    4. 个人信息提取 → user_profiles (personal_facts)
```
