# 04 — 数据库

数据库使用 Supabase (PostgreSQL + pgvector 扩展)。表结构变更通过 `migrations/` 目录下的 SQL 文件管理。

---

## 核心表（supabase.schema.json 中记录）

### `transactions` — 全类型生活记录

所有用户产生的数据统一存储在此表：记账、碎碎念、计时、工作记录、收藏等。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `created_at` | TIMESTAMPTZ | 创建时间（支持前端指定日期） |
| `type` | TEXT | 记录类型：`记账` / `whisper` / `timing` / 其他 |
| `content` | TEXT | 原始文本内容 |
| `amount` | NUMERIC | 金额（记账专用） |
| `item_id` | UUID → `items.id` | 关联物品 |
| `item_name_snapshot` | TEXT | 物品名称快照 |
| `brand_snapshot` | TEXT | 品牌快照 |
| `mood` | TEXT | 心情 emoji（碎碎念专用） |
| `finance_category` | TEXT | 记账分类：衣/食/住/行/其他 |
| `necessity` | BOOLEAN | 必要性：true=必需, false=非必需 |
| `repurchase_index` | INTEGER | 复购指数 1-5 |
| `review` | TEXT | 用户点评/感受 |
| `details` | TEXT | 客观规格信息 |
| `ai_metadata` | JSONB | AI 解析的完整元数据 |
| `embedding` | vector(1536) | pgvector 向量（text-embedding-3-small） |
| `search_vector` | tsvector | PostgreSQL 全文搜索向量 |
| `timing_type` | TEXT | 计时类型：sleep/life/work/play |
| `start_time` | TIMESTAMPTZ | 计时开始时间 |
| `end_time` | TIMESTAMPTZ | 计时结束时间 |
| `duration` | INTEGER | 计时时长（秒） |

**索引**：
- `idx_transactions_type` on `(type)`
- `idx_transactions_created_at` on `(created_at DESC)`
- `idx_transactions_search_vector` — GIN 索引（全文搜索）
- 触发器 `transactions_search_vector_update` — 自动更新 tsvector

## 迁移添加的表（`migrations/` 目录）

### `chat_messages` — AI 对话历史

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `user_id` | UUID → `auth.users` | 所属用户 |
| `role` | TEXT | user / assistant / system |
| `content` | TEXT | 消息内容 |
| `client_id` | TEXT | 客户端幂等 ID（UNIQUE） |
| `created_at` | TIMESTAMPTZ | 创建时间 |

**RLS**：用户只能访问自己的消息（`auth.uid() = user_id`）

`client_id` 用途：
- 前端用 `{timestamp}-{random}` 生成，防止重复插入
- 主动消息用 `proactive-{timestamp}` 标识

### `media_items` — 书影清单

记录用户看过的书籍和影片，追踪阅读/观看状态。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `user_id` | UUID → `auth.users` | 所属用户 |
| `title` | TEXT | 书名或影片名 |
| `media_type` | TEXT | `book` = 书籍，`movie` = 影片 |
| `status` | TEXT | `want_to_consume` = 想看，`consuming` = 正在看，`consumed` = 看过 |
| `review` | TEXT | 最近一次非空点评缓存（完整历史见 `media_item_events`） |
| `created_at` | TIMESTAMPTZ | 条目创建时间 |
| `updated_at` | TIMESTAMPTZ | 最后修改时间（触发器自动更新） |

**索引**：`(user_id, media_type, status)`、`(user_id, created_at DESC)`

**写入方式**：主页新增/续写与 Library 状态编辑统一调用 `save_media_record` RPC。函数从 `auth.uid()` 获取用户 ID，在同一事务内更新当前快照并写入历史事件。

**迁移**：016

### `media_item_events` — 书影点评与状态事件

同一书影条目可对应多条事件，为后续按时间轴展示点评、开始阅读/观看、看完等信息提供数据基础。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `user_id` | UUID → `auth.users` | 所属用户 |
| `media_item_id` | UUID → `media_items.id` | 与 `user_id` 组成复合外键，确保只能关联自己的书影条目；删除条目时级联删除 |
| `media_title_snapshot` | TEXT | 事件发生时的标题快照 |
| `media_type_snapshot` | TEXT | 事件发生时的书籍/影片类型快照 |
| `review` | TEXT | 当次点评，可为空 |
| `status_from` | TEXT | 状态变化前的状态；纯点评事件为空 |
| `status_to` | TEXT | 状态变化后的状态；纯点评事件为空 |
| `occurred_at` | TIMESTAMPTZ | 事件实际发生时间 |
| `created_at` | TIMESTAMPTZ | 数据库写入时间 |

**约束**：每条事件必须至少包含非空 `review` 或 `status_to`。

**索引**：`(media_item_id, occurred_at DESC)`、`(user_id, occurred_at DESC)`

**旧数据回填**：迁移执行时，每个既有 `media_items` 条目会生成一条初始事件，保留原点评和当前状态，事件时间使用原 `created_at`。

**迁移**：018

## 数据库函数

### `match_life_logs(query_embedding, match_threshold, match_count)`

pgvector 余弦相似度搜索，用于 RAG 向量检索策略。

- 返回匹配的 transactions 行 + 相似度得分
- 迁移：006

### `match_daily_event_items(query_embedding, match_threshold, match_count)`

对 `daily_event_items` 表的向量相似度搜索。

- 用于记忆检索（检索历史对话相关事件）

### `transactions_search_vector_update()`

触发器函数，自动更新 `search_vector` tsvector 列（迁移 001）。

### `save_media_record(p_media_item_id, p_title, p_media_type, p_status, p_review, p_occurred_at)`

书影统一写入函数（迁移 018）：

- `p_media_item_id` 为空时创建新条目及初始事件；
- 传入已有条目 ID 时更新当前快照；
- 点评非空时更新 `media_items.review` 并新增事件；
- 状态发生变化时在事件中写入 `status_from` / `status_to`；
- 使用 `auth.uid()` 校验条目归属，前端不能指定其他用户；
- 返回更新后的 `media_items` JSON。
