## 功能名称

**主页记账面板升级** — 在主页“记账”模式中新增本月支出汇总、消费日历、选中日期的消费记录和快捷记录入口，并让日历选中日期参与新记账日期判定。

---

## 背景与动机

当前主页记账模式主要承担“输入并发送一条记录”的功能，缺少对本月消费情况的即时反馈。查看本月总支出或某天记录时，需要跳转到记账报表页；重复消费也必须再次输入并调用 AI 解析。

本次升级希望让主页记账区域同时具备：

- 快速了解本月必需、非必需及总支出；
- 通过颜色深浅感知每日消费；
- 点击日期后立即查看当天记录，并把该日期作为下一条记账的默认日期；
- 一键重复记录高频且内容稳定的消费；
- 在不明显增加底部面板高度的前提下保留“补点评”能力。

参考图只约束各模块的相对顺序与浅青绿色调，具体尺寸、字号和间距按 480px 移动端实际可用空间调整。

## 数据来源与加载

### 当前月数据

从 `transactions` 查询当前自然月内：

```text
type = '记账'
created_at >= 本月第一天 00:00
created_at < 下月第一天 00:00
```

所需字段：

```typescript
type FinanceDashboardRow = {
  id: string
  created_at: string
  amount: number | string | null
  item_name_snapshot: string | null
  necessity: boolean | null
}
```

当前月数据用于：

- 三项金额汇总；
- 日历每日金额；
- 选中日期的消费记录。

### 快捷记录历史数据

快捷记录需要从首次记录到当前月的全部记账历史。直接通过 Supabase 分页查询，每页最多 1000 行，直到返回不足一页，避免 PostgREST 单次返回上限导致统计遗漏。

所需字段：

```typescript
type FinanceQuickSourceRow = {
  id: string
  created_at: string
  amount: number | string | null
  item_id: string | null
  item_name_snapshot: string | null
  brand_snapshot: string | null
  review: string | null
  details: string | null
  finance_category: string | null
  necessity: boolean | null
  repurchase_index: number | null
  ai_metadata: Record<string, unknown> | null
}
```

当前月查询和历史快捷统计查询并行执行，使汇总与日历不必等待全部历史分页完成。

### 刷新机制

- 首次进入记账模式时加载；
- `transactions` 表发生记账类型的 INSERT / UPDATE / DELETE 时重新加载；
- 手动输入或快捷记录成功后主动刷新一次，避免等待 Realtime；
- 页面重新获得焦点时补拉一次，覆盖移动端后台恢复和 Realtime 暂时断线；
- 多个短时间内连续事件使用轻量防抖，避免重复请求。

## 本月支出汇总栏

从左到右显示：

1. 必需支出；
2. 本月总支出；
3. 非必需支出。

每项第一行显示名称，第二行显示格式化金额。

### 必要性统计规则

数据库当前语义保持不变：

| `necessity` | 归类 |
|-------------|------|
| `true` | 必需支出 |
| `false` | 非必需支出 |
| `null` | 非必需支出 |

计算公式：

```text
必需支出 = Σ amount，其中 necessity = true
非必需支出 = Σ amount，其中 necessity = false 或 null
总支出 = 必需支出 + 非必需支出
```

补充规则：

- `amount = null` 或无法转换为有效数字时不参与金额计算；
- 负数金额按原值抵扣；
- 金额统一显示两位小数；
- 当前月内日期晚于今天的记录暂不进入主页汇总和日历，到对应日期后自动纳入。

## 消费日历栏

### 月份与排列

- 暂时固定显示设备本地时间对应的当前月份；
- 标题格式为 `2026年6月`；
- 每周从周一开始，七列排列；
- 月初前的占位格不显示边框和文字；
- 今天之后的日期显示日期数字，但保持米色底、不显示金额且不可点击；
- 暂不提供上月、下月切换，为后续月份选择预留组件接口。

### 日期方格

方格内部：

- 第一行：日期数字；
- 第二行：当日消费总金额；
- 当日无有效金额记录时，第二行留空；
- 长数字使用紧凑字号，避免撑破方格；
- 默认选中今天；
- 选中日期后，边框和方格文字使用高亮色；
- 点击已选中的日期不取消选择，始终保证有一个有效选中日期。

### 颜色分级

使用四档浅青绿色，颜色由浅到深代表当天消费由低到高。

统计样本仅包含：

- 今天及以前；
- 至少存在一条有效金额记账；
- 以当日全部有效金额的带符号合计作为该日金额。

分级规则：

1. 计算样本中的最小日消费 `min` 和最大日消费 `max`；
2. 当有效消费日少于 2 天，或 `min === max` 时，所有消费日使用中间档颜色；
3. 否则按 `(dayAmount - min) / (max - min)` 归一化；
4. 将归一化结果映射为四档，最小值对应最浅档，最大值对应最深档；
5. 无消费日及未来日期保持米色底。

颜色只由前端当前数据即时计算。新记账成功或 Realtime 收到变更后重新计算，不使用 GitHub Actions，也不持久化每日最小值或最大值。

## 选中日期的消费记录栏

### 展示内容

每条记录只展示：

- `item_name_snapshot`；
- `amount`。

展示规则：

- 两列网格；
- 容器默认高度恰好显示两行，即最多四条无需滚动；
- 超出四条时容器内部允许纵向触摸滚动；
- 使用 CSS 隐藏滚动条，不在侧边显示滑块；
- 同一天内按 `created_at DESC` 排序；
- 名称过长时单行省略；
- 金额保持完整并显示两位小数；
- 无记录时显示紧凑的“当天暂无消费”空状态。

日期切换时，内部滚动位置恢复到顶部。

## 日期选择与记账日期优先级

主页新增局部状态：

```typescript
const [selectedFinanceDate, setSelectedFinanceDate] = useState(todayDayKey)
```

输入文本仍先通过 `extractDate()` 提取显式日期。最终日期规则为：

| 正文日期 | 日历日期 | 最终记录日期 |
|----------|----------|--------------|
| 无 | 今天 | 今天；不显式写 `created_at`，由数据库使用当前时间 |
| 有，且与日历一致 | 对应日期 | 正文日期 |
| 有，且与日历不一致 | 任意可选日期 | 正文日期 |
| 无 | 非今天 | 日历选中日期 |

可以简化为：

```typescript
const effectiveDate = extractedDate ?? selectedFinanceDate
```

但写入时区分：

- 无正文日期且选中今天：省略 `created_at`，保留真实发送时刻；
- 其他情况：使用最终日期当地中午 12:00 转为 ISO，避免时区换日；
- 正文显式日期始终优先，包括正文显式输入的未来日期；
- 日历本身禁止点击未来方格。

当选中日期不是今天时，在输入框附近显示紧凑提示，例如“记录到 6月20日”，但不把日期文字写入输入框正文。

补点评模式只更新原交易的点评和可选属性，不修改原交易日期，因此不受当前日历选择影响。

## 快捷记录按钮栏

### 候选组合

一组快捷记录由以下三个值共同确定：

```text
item_name_snapshot + amount + review
```

标准化规则：

- `item_name_snapshot` 去除首尾空白；为空的记录不参与；
- 金额转换为“分”的整数后比较，保证页面两位小数语义下的同金额稳定分组；
- `review` 去除首尾空白；
- `review = null`、空字符串或纯空白统一视为“无点评”；
- `amount <= 0` 或金额无效的记录不生成快捷按钮，但仍按带符号金额参与汇总和日历。

### 频率条件

每个完整组合必须同时满足：

```text
总出现次数 >= 3
总出现次数 ÷ 包含首月和当前月在内的自然月数 >= 1
```

自然月数计算示例：

- 首次出现于 2026年6月，当前为 2026年6月：1 个月；
- 首次出现于 2026年4月，当前为 2026年6月：3 个月；
- 该组合出现 3 次，则月均为 `3 ÷ 3 = 1`。

未来日期记录不参与当前快捷统计。

### 排序与去重

1. 完整组合按总出现次数降序；
2. 次序相同时，最近一次出现时间更晚的优先；
3. 若不同点评组合最终显示为相同的“名称 + 金额”，只保留排序最高的组合；
4. 最终取前三个，最多展示三个按钮；
5. 无符合条件记录时不显示该栏，不占用额外高度。

按钮只显示：

```text
item_name_snapshot + amount
```

### 点击后的写入

点击按钮后，不调用 `/api/parse-transaction`，直接以该组合最近一条记录为模板，复制：

- `amount`；
- `item_id`；
- `item_name_snapshot`；
- `brand_snapshot`；
- `review`；
- `details`；
- `finance_category`；
- `necessity`；
- `repurchase_index`；
- `ai_metadata`。

`content` 不直接复制旧值，避免旧正文中的日期或无关文字被带入。改为生成稳定文本：

```text
快捷记录：{item_name_snapshot} {格式化金额}
```

日期规则：

- 日历选中今天：省略 `created_at`，使用实际点击时刻；
- 日历选中历史日期：写入该日期当地中午 12:00；
- 快捷记录不读取输入框中的日期或正文，因为它不经过输入框发送。

其他行为：

- 插入期间禁用全部快捷按钮，防止连续点击产生重复记录；
- 成功后触发向量化、刷新汇总/日历/当天记录/快捷统计，并显示“已记录”；
- 失败时显示错误 Toast，不清空输入框，也不改变当前日期选择。

## “补点评”按钮

现有大尺寸“上一条记账待补点评”卡片取消。

当最近一条记账没有 `review`，且 `ai_metadata.review` 也为空时：

- 在“衣 / 食 / 住 / 行 / 其他”同一行最右侧显示“补点评”按钮；
- 按钮使用与分类胶囊一致的高度；
- 点击后进入现有补点评模式；
- 激活时按钮高亮并显示“补充中”；
- 输入框 placeholder 显示 `给「条目名称」补点评…`，让用户仍能识别目标；
- 再次点击按钮取消补点评，并清除从目标记录带入的分类、必要性和回购指数；
- 补点评成功后退出该模式，并重新检查最新一条记账是否仍待点评。

补点评模式沿用现有规则：

- 输入文字作为点评；
- 当前选择的分类、必要性、回购指数可同时补充到原记录；
- 不创建新交易；
- 不修改原金额和日期；
- 日历选择及快捷记录不改变补点评目标。

没有待补点评记录时不显示按钮，也不预留空位。

## 加载、空状态与错误处理

- 当前月数据加载时，汇总和日历显示轻量骨架或占位，不闪烁旧月份；
- 当前月无记录时：
  - 三项汇总均为 `¥0.00`；
  - 日历正常显示，所有过去日期为米色；
  - 今天记录栏显示“当天暂无消费”；
- 快捷历史仍在加载时不阻塞输入、分类和普通发送；
- 快捷历史加载失败时不显示快捷按钮，只显示一次短 Toast；
- 当前月查询失败时显示紧凑错误提示，并允许用户继续记账；
- Realtime 刷新失败时保留上一次成功数据；
- 页面跨过午夜或从后台恢复时，重新计算今天、当前月和默认可选范围；
- 若进入新月份且原选中日期属于上个月，自动把选中日期重置为新的今天。

## 性能与数据量

- 当前月查询只读取展示所需字段；
- 历史快捷统计分页读取，避免单次 1000 行上限；
- 当前月 UI 与历史快捷统计并行加载；
- 派生统计使用 `useMemo` 或 Hook 内纯函数，避免每次输入字符都重新遍历历史记录；
- Realtime 事件使用防抖刷新；
- 本项目为单用户应用，第一版不新增数据库聚合 RPC；
- 若未来历史记录量明显增大，再将快捷统计迁移为 Supabase RPC，不占用 Vercel Function 名额。

## 边缘情况

- [ ] `necessity = null` 正确计入非必需支出。
- [ ] 金额为字符串、零、负数或 `null` 时按各模块规则处理。
- [ ] 当月仅有一个消费日时使用中间档颜色。
- [ ] 多个消费日金额完全相同时使用中间档颜色。
- [ ] 退款使某日净金额为负数时仍显示该金额，并参与当月带符号汇总。
- [ ] 今天之后方格不可点击且不显示未来记录金额。
- [ ] 正文日期与日历日期不一致时，正文日期优先。
- [ ] 选中历史日期但正文无日期时，记录写入选中日期。
- [ ] 补点评不修改原记录日期。
- [ ] 快捷组合中的空点评与 `null` 点评视为同组。
- [ ] 同名同金额但点评不同的多个合格组合只显示一个按钮。
- [ ] 快捷记录模板对应的 `item_id` 后续不存在时，插入失败并提示，不静默创建错误关联。
- [ ] 历史记录超过 1000 条时分页统计仍完整。
- [ ] Realtime 收到 DELETE 时汇总、日历和快捷统计同步减少。
- [ ] 当天超过四条记录时可以手指纵向滑动且不显示滚动条。
- [ ] 长名称和大额数字不撑破 480px 布局。

## 已确认的设计决策

用户已于 2026-06-25 明确确认：

1. `necessity = true` 为必需；`false` 和 `null` 均计入非必需。
2. 快捷记录“月均一次以上”按“总次数 ÷ 首次出现月至当前月的自然月数”计算，并同时要求总次数不少于三次。
3. 快捷记录复制符合组合的最近一条记录属性；相同名称和金额但不同点评时，只保留出现次数最高的合格组合。
4. 正文存在日期时正文日期优先；正文无日期时使用日历选中日期；选中今天且正文无日期时按真实发送时刻记录。
5. 今天之后的日历方格不可点击。
6. 第一版固定展示当前月，不提供月份切换。
7. 原大号补点评卡片改为分类栏最右侧的紧凑按钮。
8. 日历周一开头、四档浅青色、当天记录两列两行、隐藏滚动条、负数抵扣总额等细节按本方案执行。
