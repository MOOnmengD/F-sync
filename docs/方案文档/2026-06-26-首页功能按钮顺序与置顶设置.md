# 首页功能按钮顺序与置顶设置

---

## 功能名称

首页功能按钮顺序与置顶设置。

---

## 背景与动机

主页顶部 8 个记录模式按钮已从双行改为单行横向滑动，以节省纵向空间。但单行滑动后，排在后面的高频功能需要额外滑动才能访问，排在前面的低频功能占用了首屏位置。

为降低主页操作成本，本功能允许用户在设置页调整主页功能按钮的展示顺序，并支持最多 3 个置顶按钮。主页顶部展示时，置顶按钮固定显示在左侧，剩余按钮保留横向滑动。

---

## 设计目标

- [ ] 主页顶部默认固定显示「记账」「理财」「书影」3 个置顶按钮。
- [ ] 用户可在设置页调整功能按钮顺序，并选择最多 3 个置顶按钮。
- [ ] 置顶按钮固定显示，未置顶按钮继续横向滑动，保持节省纵向空间的设计。
- [ ] 配置通过现有 `user_settings.settings` 同步云端，不新增 API、不新增数据库表。
- [ ] 设置页从单一 AI 设置页调整为顶层「设置」页，包含「功能按钮顺序」和「AI 设置」两个折叠入口。

## 设计方案

### 数据流

```text
进入 Settings
  → loadFromCloud() 拉取 user_settings.settings
  → 读取 homeModePreferences
  → 无配置时使用默认：置顶 finance/invest/media，顺序 finance/invest/media/review/note/work/save/timeline

用户在「功能按钮顺序」中调整
  → 本地草稿更新 pinnedModes / modeOrder
  → 点击保存
  → updateSettings({ homeModePreferences })
  → saveToCloud()

进入 Home
  → loadFromCloud() 拉取设置
  → normalize homeModePreferences
  → 左侧固定渲染 pinnedModes
  → 右侧横向滑动渲染其余 modes
```

### 数据库变更

不新增表、不新增迁移。

现有 `user_settings.settings` 是 JSONB，可直接扩展字段：

```json
{
  "homeModePreferences": {
    "pinnedModes": ["finance", "invest", "media"],
    "modeOrder": ["finance", "invest", "media", "review", "note", "work", "save", "timeline"]
  }
}
```

兼容策略：

- 旧云端设置没有 `homeModePreferences` 时使用默认值。
- `pinnedModes` 只保留合法 `QuickMode`，最多 3 个，去重。
- `modeOrder` 只保留合法 `QuickMode`，缺失的新模式自动追加到末尾。
- 若某个置顶模式不在 `modeOrder` 中，以默认顺序补齐。

### API 设计

不新增 API。沿用 `useSettingsStore.saveToCloud()` 写入 `user_settings.settings`。

### 前端组件设计

#### 设置页结构

`/settings` 页标题从「AI 设置」改为「设置」。

页面包含两个顶层折叠区：

1. 「功能按钮顺序」
   - 展示 8 个功能模式。
   - 每行包含：拖拽手柄样式图标、模式名称、置顶开关/按钮、上移、下移。
   - 复用 Chat 页面 `API 配置` 中的排序编辑设计：卡片列表、上移/下移按钮、保存按钮、已保存反馈。
   - 拖拽排序可保留为增强能力，但移动端主路径以上移/下移为准。

2. 「AI 设置」
   - 迁移当前 Settings 页面已有内容。
   - 保留现有「文本解析」「图像解析」「语音合成」「对话模型」等内部折叠卡片。
   - 原有保存逻辑不变。

#### 设置字段

建议新增类型：

```typescript
export type HomeModePreferences = {
  pinnedModes: QuickMode[]
  modeOrder: QuickMode[]
}
```

并在 settings store 中增加默认值：

```typescript
const DEFAULT_HOME_MODE_PREFERENCES: HomeModePreferences = {
  pinnedModes: ['finance', 'invest', 'media'],
  modeOrder: ['finance', 'invest', 'media', 'review', 'note', 'work', 'save', 'timeline'],
}
```

`AISettings` 当前名称偏 AI 配置，但已作为 `user_settings.settings` 的整体前端设置对象使用。为降低改动范围，本次优先在该对象中追加 `homeModePreferences`，不做全局重命名。

#### Home 顶部模式栏

现状：

```text
整个按钮组横向滚动
```

调整后：

```text
[固定置顶按钮 1] [固定置顶按钮 2] [固定置顶按钮 3] | [其余按钮横向滑动...]
```

布局建议：

- 外层仍保持单行，不恢复双行。
- 置顶区域 `shrink-0`，最多 3 个按钮。
- 剩余区域 `flex-1 min-w-0 overflow-x-auto`。
- 按钮仍使用 `PillButton`，保持现有马卡龙视觉。

## 边缘情况

- [ ] 云端设置尚未加载：Settings 保存按钮禁用或提示同步中，沿用现有逻辑。
- [ ] 本地旧设置缺少新字段：自动使用默认置顶与默认顺序。
- [ ] 云端字段损坏或包含非法 mode：过滤非法值并补全默认值。
- [ ] 用户选择超过 3 个置顶：阻止第 4 个置顶，并显示轻量提示。
- [ ] 用户取消所有置顶：允许，但主页只显示横向滑动区；也可在 UI 上提示“建议保留 1-3 个置顶”。
- [ ] 新增 QuickMode 后：缺失模式自动追加到顺序末尾，避免按钮消失。
- [ ] 小屏宽度不足：置顶最多 3 个，剩余按钮进入右侧横向滚动，避免换行增加高度。

---

## 与现有功能的交互

- Home 的 `homeMode` 当前模式仍存放在 `useUi`，本功能只影响按钮排列，不改变模式切换语义。
- Settings 继续使用 `useSettingsStore` 的 `loadFromCloud()` / `saveToCloud()`。
- Chat 页面 AI 设置弹窗不受影响；它继续管理对话 Prompt 和 `apiConfigs`。
- `/settings` 页面会从「AI 设置专页」变为「设置聚合页」，原有 AI 配置作为顶层「AI 设置」折叠区保留。
- 不影响数据库表结构和 Vercel Serverless Function 数量。

## 实现步骤

1. 在 `settings.ts` 中新增 `HomeModePreferences` 默认值、字段类型、云端合并与本地 persist 深度合并兼容。
2. 在 `Home.tsx` 中把硬编码按钮改为由 `modeOrder + pinnedModes` 派生渲染。
3. 在 `Settings.tsx` 中新增顶层设置折叠结构，并把现有 AI 设置内容迁移进「AI 设置」折叠区。
4. 在 `Settings.tsx` 中新增「功能按钮顺序」编辑区，支持置顶、上移、下移、保存和已保存状态。
5. 执行 `npm run build` 验证 TypeScript 与生产构建。
6. 更新 `docs/02-前端页面.md`、`docs/04-数据库.md`、`docs/07-状态管理与数据流.md`。

## 验收标准

- [ ] 主页首次加载时，「记账」「理财」「书影」固定显示在模式栏左侧。
- [ ] 其余 5 个按钮在右侧保持单行横向滑动。
- [ ] 设置页显示顶层「功能按钮顺序」与「AI 设置」折叠入口。
- [ ] 在「功能按钮顺序」中调整顺序并保存后，回到主页可看到顺序变化。
- [ ] 选择置顶按钮并保存后，主页固定区随之变化，最多 3 个。
- [ ] 刷新页面或重新打开应用后，顺序与置顶配置仍保留。
- [ ] 云端无新字段或字段异常时，应用不报错，并回落到默认配置。
- [ ] `npm run build` 通过。
