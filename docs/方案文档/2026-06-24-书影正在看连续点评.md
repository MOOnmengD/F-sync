# 书影“正在看”连续点评 — 设计文档

> 状态：已实现（待在 Supabase 执行迁移并部署后做真实数据验收）
> 创建日期：2026-06-24
> 实现日期：2026-06-24

---

## 功能名称

**书影“正在看”连续点评** — 在主页书影记录入口快速选中正在阅读/观看的条目，为同一条目持续新增多条点评，并同步记录状态变化，为后续书影时间轴提供数据基础。

---

## 背景与动机

当前 `media_items` 表把条目状态和点评都存在同一行中，其中 `review` 只能保存一段文本。主页每次发送书影记录都会创建一个新的 `media_items` 条目，无法明确表达：

- 同一本书或同一部影片阅读/观看期间产生的多次点评；
- 某次点评发生的时间；
- 条目从“想看”变为“正在看”、再变为“看过”的时间；
- 后续按时间轴展示点评与状态事件。

本功能先解决主页快速续写与底层数据结构问题。本次不实现书影时间轴页面，但数据库从一开始按“条目 + 多条事件”建模，避免以后再拆分拼接文本。

---

## 设计目标

- [ ] 主页进入“书影”模式时，展示当前状态为“正在看”的书籍/影片标题胶囊。
- [ ] 点击标题胶囊后，自动选中该条目的类型和当前状态。
- [ ] 选中已有条目时，输入框内容直接作为该条目的一条新点评，不再调用 AI 解析标题。
- [ ] 同一个书影条目可保存多条带时间的点评。
- [ ] 发送时若状态改为“看过”，条目立即退出“正在看”胶囊区域。
- [ ] 每次状态变化都形成独立事件，为后续时间轴展示保留准确数据。
- [ ] 保持现有书影列表卡片及 Florian 当前书影查询的兼容性。

## 设计方案

### 核心数据模型

继续使用 `media_items` 表保存书影条目的当前快照：

- 当前标题与类型；
- 当前状态；
- `review` 保存最近一次非空点评，供现有列表卡片和旧查询兼容使用。

新增 `media_item_events` 表保存历史事件：

- 一条点评是一条事件；
- 一次状态变化是一条事件；
- 同一次发送可以同时包含点评和状态变化；
- `occurred_at` 表示事件实际发生时间，`created_at` 表示写入数据库的时间；
- 本次统一使用发送时刻作为 `occurred_at`，以后实现时间轴时可支持补录历史日期。

### 数据流

#### 新增书影条目

```text
未选择“正在看”标题
  → 用户输入“标题 + 可选点评”
  → /api/parse-media 解析标题和点评
  → 调用 save_media_record RPC
  → 原子创建 media_items 当前快照
  → 原子创建 media_item_events 初始事件
  → 若状态为“正在看”，刷新后出现在标题胶囊区域
```

#### 为正在看的条目新增点评

```text
点击“正在看”标题胶囊
  → 记录 selectedMediaItemId
  → 自动选中对应书籍/影片类型
  → 自动选中“正在看”
  → 输入框内容全部视为新点评，不调用 AI 标题解析
  → 调用 save_media_record RPC
  → 原子更新 media_items.review / status
  → 原子插入一条 media_item_events
  → 状态仍为“正在看”：标题胶囊保留
  → 状态变为其他状态：标题胶囊移除
```

#### 从书影清单页编辑条目

```text
编辑标题/类型/状态
  → 调用同一个 save_media_record RPC
  → 标题/类型只更新当前快照
  → 状态发生变化时新增状态事件
  → 不再从编辑弹窗直接覆盖历史点评
```

### 数据库变更

迁移文件计划命名为 `migrations/018_media_item_events.sql`。

```sql
CREATE UNIQUE INDEX idx_media_items_id_user
  ON media_items (id, user_id);

CREATE TABLE media_item_events (
  id                   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id              UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  media_item_id        UUID NOT NULL,
  media_title_snapshot TEXT NOT NULL,
  media_type_snapshot  TEXT NOT NULL
                       CHECK (media_type_snapshot IN ('book', 'movie')),
  review               TEXT,
  status_from          TEXT
                       CHECK (
                         status_from IS NULL OR
                         status_from IN ('want_to_consume', 'consuming', 'consumed')
                       ),
  status_to            TEXT
                       CHECK (
                         status_to IS NULL OR
                         status_to IN ('want_to_consume', 'consuming', 'consumed')
                       ),
  occurred_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_at           TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (
    NULLIF(BTRIM(review), '') IS NOT NULL
    OR status_to IS NOT NULL
  ),
  FOREIGN KEY (media_item_id, user_id)
    REFERENCES media_items(id, user_id)
    ON DELETE CASCADE
);

CREATE INDEX idx_media_item_events_item_time
  ON media_item_events (media_item_id, occurred_at DESC);

CREATE INDEX idx_media_item_events_user_time
  ON media_item_events (user_id, occurred_at DESC);

ALTER TABLE media_item_events ENABLE ROW LEVEL SECURITY;

CREATE POLICY media_item_events_user_policy
  ON media_item_events
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

### 统一写入 RPC

新增数据库函数 `save_media_record(...)`，同时支持：

1. `p_media_item_id IS NULL`：创建新条目及初始事件；
2. `p_media_item_id IS NOT NULL`：更新已有条目，并按需新增点评/状态事件。

计划参数：

```sql
save_media_record(
  p_media_item_id UUID,
  p_title TEXT,
  p_media_type TEXT,
  p_status TEXT,
  p_review TEXT,
  p_occurred_at TIMESTAMPTZ
)
```

函数规则：

- 只使用 `auth.uid()` 作为当前用户，不接受前端传入 `user_id`；
- 已有条目必须属于当前用户；
- 新建时标题、类型、状态必填；
- 已有条目允许修改标题、类型和状态；
- `p_review` 非空时：
  - 写入一条新事件；
  - 更新 `media_items.review` 为最新点评；
- 状态发生变化时，在同一条事件中写入 `status_from` 与 `status_to`；
- 只有标题/类型变化时不生成时间轴事件；
- 所有操作在同一个数据库事务中完成；
- 返回更新后的 `media_items` 行，供前端立即更新胶囊列表。

### 旧数据迁移

迁移执行时，为每个已有 `media_items` 条目补一条初始事件：

- `media_item_id` 指向原条目；
- `review` 使用原 `media_items.review`；
- `status_from = NULL`；
- `status_to` 使用条目当前状态；
- `occurred_at` 使用条目 `created_at`；
- 标题与类型写入快照字段。

这样现有点评不会丢失，并可在未来时间轴中作为最早的一条记录显示。

### Agent 查询兼容

保留现有 `media_library` 数据域读取 `media_items`，用于查询条目的当前状态和最新点评。

新增只读数据域 `media_history`，读取 `media_item_events`：

| 字段 | 用途 |
|------|------|
| `media_title_snapshot` | 事件发生时的书名/影名 |
| `media_type_snapshot` | 事件发生时的类型 |
| `review` | 当次点评 |
| `status_from` / `status_to` | 当次状态变化 |
| `occurred_at` | 事件时间 |

这样 Florian 既能查询“现在正在看什么”，也能在需要时查询某本书/影片的历史点评。

## 前端组件设计

### 主页局部状态

不新增 Zustand 字段，以下状态只在 `Home.tsx` 内使用：

```typescript
type ActiveMediaItem = {
  id: string
  title: string
  mediaType: MediaType
  status: 'consuming'
  updatedAt: string
}

const [activeMediaItems, setActiveMediaItems] = useState<ActiveMediaItem[]>([])
const [activeMediaLoading, setActiveMediaLoading] = useState(false)
const [selectedMediaItemId, setSelectedMediaItemId] = useState<string | null>(null)
```

### “正在看”标题胶囊区域

- 位置：现有书影类型/状态胶囊上方，与用户截图一致；
- 数据：当前用户所有 `status = 'consuming'` 的条目；
- 排序：`updated_at DESC`，最近记录过的条目排在前面；
- 多条时自动换行；
- 长标题限制单个胶囊最大宽度，超出省略，避免挤坏移动端布局；
- 无正在看条目时不渲染该行；
- 加载失败时不阻断普通书影新增，只给出短 Toast。

### 选中与取消

- 点击未选中的标题：
  - 选中该标题胶囊；
  - `mediaType` 设置为条目类型；
  - `mediaStatus` 设置为 `consuming`；
  - 输入框 placeholder 改为 `给《标题》写一条新点评…`。
- 再次点击已选中的标题：
  - 取消目标；
  - 类型和状态恢复未选中；
  - 回到新增书影模式。
- 选中已有条目后点击另一个“书籍/影片”类型：
  - 取消已有条目目标；
  - 切换到新增书影模式；
  - 防止把已有书籍误改成影片，或反之。
- 状态按钮仍可切换，用于在发送本条点评时同步完成状态变化。

### 发送成功后的状态

- 清空文本框；
- 清空当前标题选择，避免下一条文字误记到同一条目；
- 清空类型和状态选择；
- 若条目仍为“正在看”，标题胶囊继续显示但不选中；
- 若条目已变为“想看”或“看过”，标题胶囊立即移除；
- 新建条目若状态为“正在看”，发送成功后加入标题胶囊列表。

### 数据刷新

- 用户进入主页书影模式时拉取一次；
- `media_items` 出现 INSERT / UPDATE / DELETE Realtime 事件时重新拉取；
- 页面重新获得焦点时补拉一次，覆盖 Realtime 暂时断开等情况；
- 若当前选中的条目已被删除或不再是“正在看”，自动取消选择。

### 书影清单页调整

现有编辑弹窗的“点评”输入框会覆盖 `media_items.review`，与多点评模型冲突。建议本次同步调整为：

- 编辑弹窗只编辑标题、类型、状态；
- 状态变化通过 `save_media_record` 写入事件；
- 卡片继续显示 `media_items.review`（最新点评）；
- 历史点评的编辑/删除留到未来时间轴功能中实现。

## 边缘情况

- [ ] 同时有多本书/多部影片正在看：标题胶囊自动换行并按最近更新排序。
- [ ] 标题过长：胶囊内单行省略，不撑破 480px 布局。
- [ ] 选中条目后被其他页面改为“看过”或删除：自动取消选中。
- [ ] 发送失败：保留当前选中目标并恢复输入文本，用户可直接重试。
- [ ] AI 解析失败：只影响新增条目；给已有条目新增点评时不调用 AI。
- [ ] 点评为空：主页发送按钮维持现有空文本不发送规则；书影清单页可单独修改状态。
- [ ] 状态未变化：事件只保存点评，不重复制造状态变化。
- [ ] 点评与状态同时变化：保存为同一条事件，时间轴可同时显示文字与“已看完”。
- [ ] 删除书影条目：依靠外键 `ON DELETE CASCADE` 同步删除全部事件。
- [ ] 旧数据：迁移为初始事件，不丢失当前点评。
- [ ] 重复标题：本次不做自动合并，只有显式点击标题胶囊才会关联已有条目，避免同名书影或不同版本被误合并。

## 与现有功能的交互

- `/api/parse-media` 继续用于新增书影条目，但选中已有条目后不再调用；
- `media_items.review` 从“唯一点评”调整为“最新点评缓存”，现有 Library 卡片无需立即重做；
- Library 的状态编辑会开始生成历史事件；
- Agent 的 `media_library` 保持当前查询能力，新增 `media_history` 查询多条点评；
- 不修改通用生活时间轴 `transactions`，书影事件保持在独立领域表中；
- 不新增 Serverless Function。

## 已确认的设计决策

用户已于 2026-06-24 明确同意以下方案：

1. **已有条目输入语义**：选中“正在看”标题后，输入框全部内容直接作为点评，不再让 AI 拆标题。
2. **发送后取消选中**：点评发送成功后取消当前目标，标题若仍在看则保留为未选中胶囊，降低下一条内容误关联的风险。
3. **Library 不再直接改点评**：编辑弹窗移除点评输入，只允许改标题、类型、状态；历史点评编辑以后在时间轴里做。
4. **胶囊显示条件**：只要最终状态不是 `consuming`，包括改回“想看”或改为“看过”，标题都会退出该区域。
5. **旧点评迁移**：现有 `media_items.review` 作为每个条目的第一条历史事件，事件时间使用原条目创建时间。
6. **重复标题不自动合并**：只有点击现有标题胶囊才关联旧条目；普通新增仍可创建同名条目。
