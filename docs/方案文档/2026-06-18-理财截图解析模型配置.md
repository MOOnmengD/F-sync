# 理财截图解析模型配置

> 状态：已实现
> 日期：2026-06-18
> 追加：多图上传改造已实现

---

## 功能名称

在侧边栏「设置」页新增理财截图解析模型 API 配置，并支持自定义截图解析提示词。

---

## 背景与动机

当前理财页「上传截图」已支持调用视觉模型识别基金持仓截图，但模型 API、模型名和提示词都只在服务端处理：

- `api/investment.ts` 的 `type=ocr` 读取 `OCR_AI_*` 环境变量，fallback 到 `CHAT_AI_*` → `AI_*`。
- 当前默认模型为 `doubao-vision-pro-32k`。
- 当前 OCR prompt 直接硬编码在 `api/investment.ts` 中，前端无法调整。
- `src/components/InvestmentPanel.tsx` 上传截图时只发送 `imageDataUrl`，不会携带设置页中的 API 配置。

用户希望像记账解析、影音解析、TTS 一样，在「侧边栏 → 设置」中管理理财截图解析模型，并能为养基宝截图写专门提示词。

## 设计方案

### 数据流

```
Settings 页面保存 investmentOcrConfig
  → localStorage + Supabase user_settings.settings
  → InvestmentPanel 上传截图时读取配置
  → POST /api/investment type=ocr
  → API 使用 body 配置，空值 fallback 到环境变量
  → 视觉模型返回 funds JSON
  → 前端匹配现有基金并套入本地草稿
```

### 设置结构

在 `AISettings` 中新增：

```typescript
interface InvestmentOcrConfig {
  url: string    // 空 → OCR_AI_API_URL → CHAT_AI_API_URL → AI_API_URL
  key: string    // 空 → OCR_AI_API_KEY → CHAT_AI_API_KEY → AI_API_KEY
  model: string  // 空 → OCR_AI_MODEL → CHAT_AI_MODEL → AI_MODEL → doubao-vision-pro-32k
  prompt: string // 空 → DEFAULT_INVESTMENT_OCR_PROMPT
}
```

`loadFromCloud()` 合并时使用：

```typescript
investmentOcrConfig: cloud.investmentOcrConfig ?? current.investmentOcrConfig
```

### API 设计

继续使用现有端点，不新增文件：

```http
POST /api/investment
```

输入：

```json
{
  "type": "ocr",
  "imageDataUrl": "data:image/webp;base64,...",
  "url": "https://example.com/v1",
  "key": "sk-...",
  "model": "vision-model-name",
  "prompt": "自定义识别提示词"
}
```

输出保持不变：

```json
{
  "funds": [
    {
      "fund_name": "华夏创业板指数E",
      "holding_cents": 231114,
      "profit_rate": 0.2304
    }
  ]
}
```

配置优先级：

```typescript
body.url   → OCR_AI_API_URL → CHAT_AI_API_URL → AI_API_URL
body.key   → OCR_AI_API_KEY → CHAT_AI_API_KEY → AI_API_KEY
body.model → OCR_AI_MODEL   → CHAT_AI_MODEL   → AI_MODEL → doubao-vision-pro-32k
body.prompt → DEFAULT_INVESTMENT_OCR_PROMPT
```

### 默认 Prompt

默认提示词建议写为：

```text
你是一个基金持仓截图识别助手。请仔细查看这张养基宝/支付宝基金持仓页面截图，并只提取持仓列表中的基金行。

截图中的表格列含义通常是：
- 第一列：基金名称。如果名称被省略号截断，只保留截图中可见的名称前缀，去掉省略号；不要凭空补全完整基金名。
- 第二列「持有金额」：当前持仓金额，也就是计算所需的当前持仓 C。
- 第三列「持有收益率」：当前持有收益率，也就是计算所需的收益率 R。
- 第四列「关联板块」或其它涨跌幅信息不参与计算，请忽略。

请忽略账户资产、场内穿透、底部指数条、累计收益、昨日收益、关联板块等汇总或行情信息。

对每一只可见基金返回：
- fund_name: 基金名称或可见名称前缀，字符串
- holding_cents: 持有金额，单位为分的整数。例如 2,311.14 元返回 231114
- profit_rate: 持有收益率的小数形式。例如 +23.04% 返回 0.2304，-11.82% 返回 -0.1182

请严格按照以下 JSON 格式返回，不要包含 Markdown、解释或其它文字：
{
  "funds": [
    { "fund_name": "华夏创业板指数E", "holding_cents": 231114, "profit_rate": 0.2304 }
  ]
}

注意：
- 只识别截图中可见的基金行，未出现的基金不要返回。
- 如果某个字段看不清，请将对应字段设为 null，不要编造数值。
- 金额中的逗号、空格和货币符号不影响数值识别。
- profit_rate 必须是小数，不是百分数字符串。
```

### 前端组件设计

`Settings.tsx` 新增折叠卡片：

- 分区：可放入「文本解析」之后，标题使用「图像解析」。
- 卡片标题：`理财截图解析`
- 副标题：`investment ocr`
- 字段：
  - API URL
  - API Key
  - 模型
  - Prompt（单个大文本框，留空使用默认）
  - 重置 Prompt 按钮：把本地 prompt 设为空

可以复用现有 `AccordionCard` 和 `KeyInput`，新增一个轻量的 `InvestmentOcrSection`。

### 截图信息是否够用

对调仓计算来说，截图信息基本够用：

- 第二列「持有金额」可作为当前持仓 C。
- 第三列「持有收益率」可作为当前收益率 R。
- 当前计算不需要「关联板块」、当日涨跌、账户总资产或底部指数。

需要注意的限制：

- 截图只能识别可见行；如果基金列表没有全部显示，需要多张截图或长截图。
- 截图中的基金名有省略号截断，模型不应硬猜全名；前端匹配应按可见前缀匹配现有 `investments.fund_name`。
- 如果两个基金可见前缀相同，仍可能无法可靠匹配，需要用户在识别结果弹窗中确认或后续增加手动匹配。

### 匹配增强

当前前端匹配逻辑是名称完全相等、互相包含。为了适配截图中的 `...` / `…` 截断名，建议同步做小幅增强：

- 匹配前清理空白、省略号、中英文标点。
- OCR 名称为现有基金名前缀时视为匹配。
- 仍然不让模型编造完整名称，降低误匹配和幻觉风险。

### 多图上传追加方案

当前上传控件只读取 `files[0]`，因此一次只能处理单张截图。改造目标是允许用户一次选择多张普通截图，以替代特别长的长截图，减少最长边压缩到 1536px 后造成的文字变小问题。

前端流程：

```
用户点击「上传截图」
  → input[type=file] 增加 multiple
  → 读取 Array.from(files)
  → 逐张执行 compressImage(file)
  → 逐张 POST /api/investment type=ocr
  → 每张返回 funds 后做名称匹配
  → 按 matchedId / 标准化 fund_name 去重合并
  → 弹出同一个识别结果确认框
```

合并规则：

- 优先按 `matchedId` 去重；未匹配项按清理后的 `fund_name` 去重。
- 同一基金多次出现时，后识别到的非空 `holding_cents` / `profit_rate` 覆盖前值。
- 保留 `sourceIndex` / `sourceName` 供调试或后续展示使用，但结果弹窗不必强制显示。
- 如果部分截图识别失败，保留已成功结果并用 toast 提示失败张数；如果全部失败，则显示失败 toast，不弹空结果。

上传数量：

- MVP 不做硬限制，但建议前端可在文案中提示一次选择 2-5 张更稳。
- 每张图仍沿用 `compressImage()` 的 5MB 原图上限、WebP 0.75 和最长边 1536px 限制。
- 多张普通截图会比一张超长长截图更清晰，因为每张图独立压缩，文字不会被长截图整体缩得过小。

## 边缘情况

- [x] 用户未配置 URL/Key：API 继续使用 Vercel 环境变量；若仍缺失，返回现有错误。
- [x] 用户只填 model：URL/Key 仍可从环境变量获取。
- [x] Prompt 留空：使用默认 prompt。
- [x] Prompt 超长：暂不做前端限制，沿用当前请求体大小和模型 token 限制。
- [x] 视觉模型不支持 `image_url`：API 返回上游错误，前端 toast 提示。
- [x] OCR 返回非 JSON：沿用现有 JSON/代码块解析与错误提示。
- [x] 截图基金名截断：使用可见前缀匹配，未匹配则在结果弹窗标记「未匹配」。
- [x] 多图部分失败：保留成功结果并提示失败张数。
- [x] 多图重复基金：按匹配 ID / 标准化名称去重合并。
