# AI 消息语音朗读

> 调用 MiniMax speech-2.8-hd 模型（同步 API），为 AI 回复消息提供语音朗读功能。

---

## 背景与动机

当前 AI 对话仅支持文字阅读。在移动端使用场景下（走路、通勤等），用户不方便长时间盯着屏幕，需要语音朗读 AI 回复内容，提升使用便利性。

---

## 设计目标

- [ ] 后端新增 `/api/text-to-speech`，代理 MiniMax 同步 TTS API，负责文本预处理（Markdown 清理）
- [ ] AI 消息气泡下方新增「朗读」按钮，点击播放该条消息
- [ ] 页面 Header 右侧按钮组最左侧新增「自动朗读」开关，开启后 AI 新消息自动播放
- [ ] 多条消息时播放最新一条（打断替换）
- [ ] 环境变量仅需 `MINIMAX_API_KEY`

## 设计方案

### 数据流

```
用户点击朗读 / AI 新消息到达(自动模式)
          ↓
前端: POST /api/text-to-speech { text: "<AI 原始回复>" }
          ↓
后端: 清理 Markdown → 截断(≤10000字)
          ↓
后端: POST https://api.minimax.chat/v1/text_to_speech (同步)
          ↓
后端: 获得二进制音频数据 → 转为 base64 data URL
          ↓
前端: 收到 { audioDataUrl: "data:audio/mp3;base64,..." }
          ↓
前端: new Audio(url).play()
          ↓ (如同步到达第二个请求)
前端: 中断前一播放 → 播放最新
```

### 为什么是同步 API

- 同步 API 端点 `POST https://api.minimax.chat/v1/text_to_speech` 支持最多 **10000 字符**
- AI 单条回复通常远小于此上限（即使超长也可安全截断）
- 同步 API 一步完成，无需轮询，延迟更低、实现更简单
- 异步 API 的 5 万字上限在此场景下是过剩能力，引入不必要的轮询复杂度

### API 设计

```
POST /api/text-to-speech

输入:
{
  "text": "AI 回复的原始内容（含 Markdown，由后端负责清理）"
}

输出 (成功):
{
  "audioDataUrl": "data:audio/mp3;base64,..."
}

输出 (失败):
{
  "error": "错误描述"
}

状态码:
  200 - 成功
  400 - 参数错误（text 为空或超长）
  500 - TTS 服务异常
```

**后端处理流程**：

1. 校验 `text` 非空
2. **文本预处理**（后端负责）：
   - 移除 Markdown 语法标记（`**`/`__`、`*`/`_`、`` ` ``/```、`[]()`、`#`、`>`、`-`/`*` 列表符、`~~` 等）
   - 压缩多余空白（连续换行 → 单个换行）
   - 截断到 10000 字符（安全边界）
3. 调用 MiniMax 同步 TTS API：
   ```
   POST https://api.minimax.chat/v1/t2a_v2
   Authorization: Bearer <MINIMAX_API_KEY>
   Content-Type: application/json

   {
     "model": "speech-2.8-hd",
     "text": "<清理后的文本>",
     "voice_setting": {
       "voice_id": "Chinese (Mandarin)_Gentleman",
       "speed": 0.83
     },
     "output_format": "hex",
     "audio_setting": {
       "format": "mp3",
       "audio_sample_rate": 32000,
       "bitrate": 128000,
       "channel": 2
     }
   }
   ```
4. 接收 JSON 响应（`data.audio` 为 hex 编码的音频数据），hex→base64 转换后返回前端 `data:audio/mp3;base64,...`

**关于语气词增强**：通过在文本中插入 MiniMax 支持的语气标签（如 `(sighs)`、`(chuckle)`、`(breath)` 等）可让语音更自然，但这需要额外的 NLU 小模型来智能插入。考虑到：
- 增加一次 API 调用延迟（至少 +1-2 秒）
- 在当前模型中引入额外的幻觉风险
- MiniMax speech-2.8-hd 本身的自然度已经很高

→ **暂不做**，后续如有需求可作为独立优化项。

### 前端设计

#### 1. 全局音频播放（组件级）

在 `Chat.tsx` 中用 `useRef` 持有一个音频播放控制器：

```typescript
// 简单的"最新优先"播放器：新请求到达时自动中断旧的
const audioCtxRef = useRef<{ url: string; audio: HTMLAudioElement } | null>(null)

async function requestAndPlay(text: string) {
  try {
    const res = await fetch('/api/text-to-speech', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ text })
    })
    if (!res.ok) return // 静默失败
    const { audioDataUrl } = await res.json()

    // 打断旧播放
    audioCtxRef.current?.audio.pause()
    const audio = new Audio(audioDataUrl)
    audioCtxRef.current = { url: audioDataUrl, audio }
    await audio.play()
  } catch {
    // 静默失败
  }
}
```

#### 2. 消息气泡朗读按钮（MessageBubble 内）

在 AI 消息气泡下方时间戳行，与现有的 `刷新` 和 `删除` 按钮并列。按钮状态通过 `Chat` 组件下传的回调管理。

**位置示意**（现有代码 `Chat.tsx` L1463-1481 附近）：

```
[时间戳] [朗读🔊] [刷新🔄] [删除🗑]    ← AI 消息（role === 'assistant' 且 content 非空）
[时间戳] [刷新🔄] [删除🗑]              ← 用户消息（无朗读按钮）
```

**按钮实现**：

```tsx
<button
  onClick={() => onReadAloud?.(msg)}
  disabled={isReading}
  className="p-1 rounded-full text-base-text/20 hover:text-[#B4AEE8] hover:bg-[#F0EEFF] active:scale-90 transition-all duration-150"
>
  {isReading ? <Loader2 size={12} className="animate-spin" /> : <Volume2 size={12} />}
</button>
```

- `isReading` 状态由 `Chat` 组件管理，标识当前正在请求/播放的消息 ID
- 仅对 AI 消息（`role === 'assistant'`）且 `content` 非空时显示
- typing 状态时不显示

#### 3. 自动朗读开关（Header 右侧按钮组）

位置：在 Header 右侧按钮组**最左侧**，与 Settings / DailyEvents / ProfileDiary / Back 使用相同样式。

**位置示意**：

```
[Sparkles AI 助手]                    [🔊自动] [⚙设置] [📋事件] [📖记忆] [←返回]
```

**实现**：

```tsx
const [autoReadEnabled, setAutoReadEnabled] = useState(() => {
  return localStorage.getItem('fsync.auto-read-tts.v1') === 'true'
})

const toggleAutoRead = useCallback(() => {
  setAutoReadEnabled(prev => {
    const next = !prev
    localStorage.setItem('fsync.auto-read-tts.v1', String(next))
    return next
  })
}, [])
```

按钮渲染（在现有按钮组中，Settings 按钮之前）：

```tsx
<button
  type="button"
  onClick={toggleAutoRead}
  className="h-10 w-10 border rounded-full bg-base-surface active:opacity-70 flex items-center justify-center transition-colors"
  style={{
    borderColor: autoReadEnabled ? '#B4AEE8' : undefined,
    color: autoReadEnabled ? '#B4AEE8' : undefined
  }}
  title={autoReadEnabled ? '自动朗读已开启' : '自动朗读已关闭'}
>
  {autoReadEnabled ? <Volume2 size={16} /> : <VolumeX size={16} />}
</button>
```

#### 4. 自动朗读触发时机

在 `sendToAi` 中，`updateMessage` 写入成功的内容后：

```typescript
// 在 updateMessage(aiMsgId, { content: cleanContent, ... }) 之后
if (autoReadEnabled && cleanContent) {
  requestAndPlay(cleanContent) // 不 await，让它在后台执行
}
```

自动朗读使用 AI 的原始 `cleanContent`（已去除思维链标签后的纯回复文本），不做二次处理。Markdown 清理由后端负责。

## 边缘情况

- [x] **加载中**：朗读按钮显示旋转图标，disabled
- [x] **空内容**：AI 消息 content 为空时，不显示朗读按钮
- [x] **超长文本**：后端截断到 10000 字符，不影响用户体验
- [x] **网络错误**：TTS 请求失败 → 静默处理，不影响页面；自动模式下也静默失败
- [x] **多条并发**：新请求到达 → `pause()` 旧音频 → 创建新实例并播放 → 实现「最新覆盖」
- [x] **用户消息**：不显示朗读按钮
- [x] **typing 状态**：消息正在流式生成中时不显示朗读按钮
